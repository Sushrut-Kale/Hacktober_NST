# VIKASA — Frontend API Contract & Integration Reference

> **Base URL:** `http://localhost:8000`  
> **Backend Framework:** FastAPI (Python 3.13)  
> **Data Format:** `application/json` (All timestamps in ISO 8601 UTC format)

---

## 1. System States & Enums

### Task Lifecycle State Machine (`TaskState`)

Tasks transition deterministically through these states. Any attempt to skip steps (e.g. executing before approving) returns HTTP `409 Conflict`.

| State | Description | Next Permitted States |
|---|---|---|
| `CREATED` | Task initialized with acceptance criteria. | `PLANNED` |
| `PLANNED` | Plan generated by Gemma 4 or deterministic fallback. | `APPROVED`, `PLANNED` (re-plan) |
| `APPROVED` | Plan explicitly approved by human/QA. Ready for execution. | `RUNNING` |
| `RUNNING` | Command currently executing in the workspace. | `VERIFYING`, `FAILED` |
| `VERIFYING` | Execution finished; evidence collected. Awaiting verification. | `VERIFIED`, `FAILED`, `REVIEW_REQUIRED` |
| `VERIFIED` | Deterministic verification passed all criteria. Terminal state. | None |
| `FAILED` | One or more criteria failed or exit code was non-zero. | `PLANNED` (re-plan), `APPROVED` (re-approve) |
| `REVIEW_REQUIRED`| Evidence is missing, ambiguous, or diff is absent. | `PLANNED` (re-plan), `APPROVED` (re-approve) |

### AI Generator Status (`GeneratorStatus`)

Used in plan generation and failure diagnosis responses to distinguish real AI inference from fallbacks:

* `AI_ACTIVE`: Plan or diagnosis was generated by local Gemma 4 (`gemma4:e4b`).
* `FALLBACK_ACTIVE`: Ollama was unavailable, timed out, or returned malformed JSON. A deterministic, structured fallback was returned.
* `AI_UNAVAILABLE`: Ollama service is unreachable or model is not loaded.

### Verification Verdict (`VerificationVerdict`)

* `VERIFIED`: All required criteria substantiated by passing evidence, exit code 0, and valid diff.
* `FAILED`: One or more commands failed (exit code != 0), missing criteria evidence, or contradictory tracebacks.
* `REVIEW_REQUIRED`: Code modifications require verification but git diff is absent or ambiguous.

## 2. API Endpoints

### A. Health & Diagnostics

#### `GET /health`
Returns general backend availability.

* **Response (`200 OK`):**
```json
{
  "status": "healthy",
  "service": "VIKASA API",
  "version": "0.1.0"
}
```

#### `GET /api/health/ollama`
Checks local Ollama service and `gemma4:e4b` model status.

* **Response (`200 OK`):**
```json
{
  "status": "AI_ACTIVE",
  "available": true,
  "model": "gemma4:e4b",
  "model_ready": true,
  "all_models": ["gemma4:e4b", "qwen2.5-coder:7b"]
}
```
*(If Ollama is stopped, `status` returns `"AI_UNAVAILABLE"` and `available: false`)*

#### `GET /api/health/antigravity`
Checks local Antigravity runtime interfaces.

* **Response (`200 OK`):**
```json
{
  "sdk_installed": false,
  "sdk_package": "google-antigravity (PyPI)",
  "cli_installed": false,
  "cli_path": null,
  "mcp_enabled": true,
  "status": "NEEDS_INSTALLATION",
  "notes": "google-antigravity 0.1.22 is available on PyPI ('pip install google-antigravity'). Local runner adapter handles execution with full deterministic evidence capture."
}
```

### B. Persistent Task Workflow

#### 1. Create Task: `POST /api/tasks`

Creates a new task in `CREATED` state.

* **Request Body (`TaskCreateRequest`):**
```json
{
  "id": "task-user-auth",
  "title": "Implement JWT authentication",
  "description": "Verify token expiry and signature validation",
  "acceptance_criteria": [
    {
      "id": "AC-1",
      "description": "Valid JWT returns HTTP 200",
      "required": true
    },
    {
      "id": "AC-2",
      "description": "Expired JWT returns HTTP 401",
      "required": true
    }
  ],
  "workspace_path": null
}
```
*Note: `id` and `workspace_path` are optional. If omitted, `id` is auto-generated and `workspace_path` defaults to the repository root.*

* **Response (`201 Created`):**
```json
{
  "id": "task-user-auth",
  "title": "Implement JWT authentication",
  "description": "Verify token expiry and signature validation",
  "acceptance_criteria": [
    {
      "id": "AC-1",
      "description": "Valid JWT returns HTTP 200",
      "required": true
    },
    {
      "id": "AC-2",
      "description": "Expired JWT returns HTTP 401",
      "required": true
    }
  ],
  "state": "CREATED",
  "project_id": "default",
  "workspace_path": null,
  "created_at": "2026-10-24T12:00:00Z",
  "updated_at": "2026-10-24T12:00:00Z",
  "approved_at": null
}
```

#### 2. List Tasks: `GET /api/tasks`

Returns all persisted tasks ordered by creation time descending.

* **Query Parameters:** `project_id` (optional)
* **Response (`200 OK`):** Array of `Task` objects.

Invokes Gemma 4 (or deterministic fallback) to produce an actionable plan, advancing state to `PLANNED`.

* **Query Parameters:** `repo_context` (optional string with file paths or snippets)
* **Response (`200 OK` - `TaskPlan`):**
```json

  "task_id": "task-user-auth",

  "generator_status": "AI_ACTIVE",
```

#### 5. Approve Task Plan: `POST /api/tasks/{task_id}/approve`

Explicit human approval gate. **Execution will be blocked with `409 Conflict` until this endpoint is called.** Advances state to `APPROVED`.

* **Request Body (optional `TaskApproveRequest`):**
```json
{
  "approved_by": "LEAD_REVIEWER",
  "notes": "Plan verified; proceed with test execution"
}
```
* **Response (`200 OK`):** Updated `Task` object with `state: "APPROVED"` and `approved_at` timestamp.
* **Error (`409 Conflict`):** If task is not in `PLANNED`, `FAILED`, or `REVIEW_REQUIRED` state.

---

#### 6. Execute Task: `POST /api/tasks/{task_id}/execute`

Executes an allowlisted command (`python`, `pytest`, `git`) in the task's approved workspace. Advances state to `VERIFYING`.

* **Request Body (`TaskExecuteRequest`):**
```json
{
  "command": "python -m pytest backend/tests/test_auth.py -v",
  "criterion_id": "AC-1",
  "timeout_seconds": 30.0
}
```
* **Security Rules:**
  - Binary must be `python`, `pytest`, or `git`.
  - Shell operators (`&&`, `||`, `|`, `>`, `<`, `$()`, unquoted `;`) return `400 Bad Request`.
  - Task must be in `APPROVED` state, otherwise returns `409 Conflict`.
* **Response (`200 OK` - `ExecutionRun`):**
```json
{
  "run_id": "run-b8f3e21a",
  "task_id": "task-user-auth",
  "started_at": "2026-10-24T12:02:00Z",
  "completed_at": "2026-10-24T12:02:02Z",
  "status": "COMPLETED",
  "command": "python -m pytest backend/tests/test_auth.py -v",
  "exit_code": 0,
  "stdout": "================ 2 passed in 0.45s ================",
  "stderr": "",
  "source": "LOCAL_EXECUTION_RUNNER",
  "git_diff": "diff --git a/backend/app/auth.py b/backend/app/auth.py\n+def verify_jwt()...",
  "evidence_items": [
    {
      "criterion_id": "AC-1",
      "evidence_type": "COMMAND_EXIT_CODE",
      "content": "Executed 'python -m pytest backend/tests/test_auth.py -v'. Exit status: 0",
      "exit_code": 0,
      "passed": true
    },
    {
      "criterion_id": "AC-1",
      "evidence_type": "TEST_OUTPUT",
      "content": "================ 2 passed in 0.45s ================",
      "exit_code": 0,
      "passed": true
    },
    {
      "criterion_id": "AC-1",
      "evidence_type": "GIT_DIFF",
      "content": "diff --git a/backend/app/auth.py...",
      "passed": true
    }
  ]
}
```

* **Query Parameters:** `run_id` (optional, verifies specific run)

## 3. Error Responses Summary

All errors return JSON with the standard FastAPI format: `{"detail": "<error_message>"}`.

| HTTP Status | Condition | Example |
|---|---|---|
| `400 Bad Request` | Malformed body, invalid workspace, or forbidden shell metacharacter. | `{"detail": "Forbidden shell separator ';' detected"}` |
| `404 Not Found` | Requested task or run does not exist. | `{"detail": "Task 'task-xyz' not found."}` |
| `409 Conflict` | Illegal state machine transition. | `{"detail": "Cannot execute task 't1' in state 'PLANNED'. Explicit user approval is required."}` |
